# 建模方法说明

本文说明模板的建模口径，便于技术交底与业务验收。

## 1. 数据流水线

```text
人工打标样本（正/负）
  → 按主键取特征（mock 生成 / spark 从 Hive 过滤）
  → 按主键哈希 + 标签分层切分训练/测试集
  → 训练集剔除否决命中客户（测试集保留用于评估）
  → 特征清洗：缺失率、常量、类别基数
  → 卡方分箱 → WOE / IV → VIF 逐步剔除 → L1 逻辑回归
  → 分值换算 → 评分卡 SQL → 本地执行 SQL 评估
```

训练与评估共用 `core/preprocess.py` 的 `prepare_dataset`，保证两侧数据口径一致。

## 2. 分箱与 WOE

- 数值型：先按分位点做初始分箱，再合并小样本箱，并按卡方统计量合并至 `max_bin`；
- 类别型（含 flag）：每个取值一箱；
- 缺失值单独成一箱，SQL 中同样单独给分；
- WOE 采用拉普拉斯平滑：`WOE = ln((bad+0.5)/(bad_total+0.5k)) - ln((good+0.5)/(good_total+0.5k))`；
- IV 为各箱 `(bad_pct - good_pct) × WOE` 之和，用于字段初筛。

## 3. 变量筛选

1. 预处理：训练集缺失率超阈值、常量、类别基数超限的字段剔除；
2. IV：`IV <= iv_threshold` 或只有单箱的字段剔除；
3. VIF：逐步计算方差膨胀因子，超过 `vif_threshold` 时剔除共线性最强的字段；
4. L1 逻辑回归：系数被压缩为 0 的字段剔除。

## 4. 评分换算

```text
score = base_score - factor × (β0 + Σ βi × WOEi)
factor = PDO / ln(2)
```

- `base_score` 为基准分，`PDO` 为好坏比翻倍时的分数跨度；
- 每个分箱的分值贡献为 `-factor × βi × WOEi`，SQL 中内联为 CASE 分支。

## 5. 业务规则

执行顺序：基础分 → 否决标记 → 负分归零 → 分值类加分 → 百分比类加分 → 封顶 → 分级。

- 否决：`veto.any` 任一条件命中即为 E，分数仍照常输出；字符串仅支持 `=` / `!=`，`!=` 在缺失时也命中；
- 加分：`score_rules` 直接加 `points`；`percent_rules` 以（归零分 + 分值类加分）为基数乘 `percent`；
- 总加分不超过 `max_total`；
- A/B/C/D 阈值取训练集基础分 75/50/25 分位点，加分后再分级。

## 6. 评估口径

- 本地 pandas 执行器按 SQL CASE 分支等价执行，不依赖 Spark / DuckDB；
- AUC / KS 用 `-score` 作为违约概率的单调替身（分数越高客户越优）；
- PSI 以训练集分数分位点为边界，比较训练 / 测试分布；
- E 客户不参与 AUC/KS/PSI，单独在 A/B/C/D/E 分层表中统计。

## 7. 已知限制

- SQL 评估器只支持本模板生成的 SQL 条件形态（`IS NULL` / `TRIM` / `IN` / `<=`），手改 SQL 后需确认可解析；
- 示例场景指标基于小样本 Mock，仅用于流程与规则验证；
- 分箱未引入单调性约束，如需业务可解释性可后续增加单调分箱。
