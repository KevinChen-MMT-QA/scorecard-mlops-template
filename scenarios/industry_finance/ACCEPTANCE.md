# 产业金融营销优先级评分卡 — 验证与验收材料

> 用途：业务方验证模型口径与规则、技术方了解模型全貌；当前指标基于离线 Mock 数据，
> 生产验收需用真实人工打标样本重跑 `python run.py train/evaluate --scenario industry_finance`。

---

## 一、模型全貌（技术方）

### 1. 目标与输出

| 项目 | 内容 |
| --- | --- |
| 模型目标 | 对产业金融客户做营销优先级排序，分数越高越优先 |
| 数据来源 | Hive 表 `mdm_m01.m01_100_mkt_icf_cust_info`，按 `part_dt` 取当日快照 |
| 唯一主键 | `unt_scl_cdt_cd` |
| 输入样本 | 人工打标的 `pos_sample_ids` / `neg_sample_ids`（csv 或 txt） |
| 输出字段 | `unt_scl_cdt_cd`、`score`、`customer_level`（A/B/C/D/E） |
| 线上产物 | `report/scorecard.sql`（单条 Hive SELECT，无 pkl、无推理代码） |

### 2. 端到端流程

```text
scenario.yaml + fields.csv + feature_engineering.sql
        │
        ├─ 人工打标样本（正/负）→ 主键集合、去重、正负冲突校验
        │
        ├─ mock / spark 取数 → spark 执行 feature_engineering.sql 多表 JOIN + 衍生字段
        │                      → mock 逐行生成源字段后，pandas 等价计算衍生字段
        │
        ├─ 主键过滤 → 训练集/测试集（70/30，按标签分层）
        │
        ├─ 预处理：数值转数值、哨兵值置缺失、flag 仅 0/1、类别去空格
        │
        ├─ 特征筛选：缺失率 > 0.9、常量、类别基数 > 50 剔除
        │
        ├─ 建模：卡方分箱 → WOE/IV（IV ≥ 0.01）→ VIF（≤ 5）→ L1 逻辑回归
        │
        ├─ 评分卡：base=100，PDO=10，分箱分值内联
        │
        ├─ 业务规则：否决 → E；基础分负分归零 → 加分（封顶 20）
        │
        └─ 产出：scorecard.sql（内嵌 engineered CTE）+ 评估报告
```

### 3. 评分与分级口径

- 评分公式：`score = base - PDO/ln2 × (β0 + Σβi·WOEi)`，SQL 中直接内联各分箱分值。
- 缺失值单独成箱并单独给分；训练集未出现的类别按 WOE=0，不贡献分。
- A/B/C/D 阈值取训练集基础分的 90/80/60 分位；当前为 `A ≥ 206.09`、`B ≥ 189.31`、`C ≥ 145.44`、`D < 145.44`。
- 阈值按基础分确定，加分后再分级，因此加分可把目标客户“拎”到更高档。
- 被否决客户从训练集剔除，测试集保留用于评估；线上 `score` 照常输出，仅等级置 E。

### 5. 特征衍生（9 个字段）

特征衍生由 `feature_engineering.sql` 统一描述，训练端（Spark 直接执行 Hive SQL、Mock 由 pandas 等价执行）和 SQL 产物端（内嵌为 `engineered` CTE）**共用同一份 SQL 原文**，保证口径一致。

| # | 衍生字段 | 中文名 | 类型 | 加工规则 | 源字段 |
| --- | --- | --- | --- | --- | --- |
| 1 | `wht_tech_co` | 是否科技型企业 | flag | 国家技术创新示范 / 国家级高新技术 / 制造业单项冠军 / 专精特新中小企业 / 科技型中小企业 / 创新型中小企业 / 硬科技赛道 **任一='1'** → `'1'`，否则 `'0'` | nation_innov_demo_ent_ind, nation_new_tech_ent_ind, manuf_champ_ent_ind, prov_srdi_mid_sml_ent_ind, st_mid_sml_ent_ind, innov_mid_sml_ent_ind, wht_hard_tech |
| 2 | `rt_rslt_idx` | 技术流评级（三分类） | category | `rt_rslt_id` 原始值 **TA1/TA2/TA3 → `'2'`**；**TB1/TB2 → `'1'`**；**其他 → `'0'`** | rt_rslt_id |
| 3 | `rto_dept_ln` | 存贷比（存款高于贷款） | flag | 存款日均 **≥1000万** 且 贷款余额 **>0** 且 存款日均 **≥3×贷款余额** → `'1'`，否则 `'0'` | dept_bal_avg_y, undisc_ln_bal |
| 4 | `rto_ln_dept` | 贷存比（贷款高于存款） | flag | 贷款余额 **≥1000万** 且 贷款余额 **>100×存款日均** → `'1'`，否则 `'0'` | undisc_ln_bal, dept_bal_avg_y |
| 5 | `credit_bal_pct_idx` | 用信余额占比介于 0~10% | flag | 用信余额占比 **>0 且 <0.1** → `'1'`，否则 `'0'` | credit_bal_pct |
| 6 | `fin_idx` | 自定义财务指标评分（百分制） | numeric | **资产负债率<65% 且 净利润>0 且 营收≥2500万 且 利润率≥10% → 100**<br>资产负债率<75% 且 净利润>0 且 营收≥1500万 且 利润率≥8% → 80<br>资产负债率<80% 且 净利润>0 且 营收≥500万 → 60<br>**否则 → 40** | ast_lia_rt, nt_pft, biz_tot_incm, sl_pm_rt |
| 7 | `wht_ipo_progress` | 是否有 IPO 进程 | flag | ipo_progress **非空** → `'1'`，否则 `'0'` | ipo_progress |
| 8 | `wht_rev_growth_rt` | 是否营业收入增长率超 10% | flag | rev_growth_rt **> 0.1** → `'1'`，否则 `'0'` | rev_growth_rt |
| 9 | `wht_credit_bal_pct` | 是否用信占比介于 0~10% | flag | 用信占比 **>0 且 ≤0.1** → `'1'`，否则 `'0'` | credit_bal_pct |

加工规则说明：

- **`rt_rslt_idx`** 覆盖原始字段 `rt_rslt_id`（原始值 `TA1/TA2/TA3/TB1/TB2/TC/TD/...` 归并为三档），业务规则"技术流 TB 及以上加分"已切换为引用 `rt_rslt_idx IN ('1','2')`；
- **`credit_bal_pct_idx` 与 `wht_credit_bal_pct`** 阈值略有不同：前者要求严格 `<0.1`，后者放宽为 `≤0.1`，分别对应"占比严格低于 10%"和"占比刚好 10% 也算"两种业务场景；
- 所有**数值型比较**均 `CAST(... AS DOUBLE)` 后再比较，Hive SQL 中 decimal/string 隐式转换可能产生精度偏差，显式 CAST 保障一致；
- 所有**字符串比较**均 `TRIM(...)` 后再比较，源表字段可能有前后空格。

### 6. SQL 结构（6 个 CTE）

| CTE | 作用 | 位置 |
| --- | --- | --- |
| `engineered` | **特征衍生 SQL**：多表 JOIN + 9 个衍生字段 CASE WHEN，由 `feature_engineering.sql` 内嵌 | `scorecard.sql` L11–103 |
| `src` | 从 `engineered` 取主键、入模字段、否决字段、加分条件字段 | L104–108 |
| `base` | 各字段分箱给分；计算 `is_veto`、`bonus_points`、`bonus_pct` | L109–142 |
| `scored` | 传递规则字段并计算基础分 `raw_score` | L143–151 |
| `bonus_calc` | 基础分负分归零 `base_pos` | L152–160 |
| `final` | 加分并 `LEAST(..., 20)` 封顶，输出 `score` | L161–173 |
| 最终 SELECT | `is_veto=1` 优先置 E，再按阈值分 A/B/C/D | L174–184 |

## 三、业务方可验证内容（验收清单）

### 3.1 规则验收

| 验收项 | 验证方法 | 通过标准 |
| --- | --- | --- |
| 否决-考核分类 | 抽取 `check_class_cd='0'` 客户 | 等级全部为 E |
| 否决-经营异常 | 抽取 `reg_st<>'正常'` 及 `reg_st` 为空客户 | 等级全部为 E |
| 否决-名单字段 | 每个名单字段抽取 `='1'` 客户 | 等级全部为 E |
| 否决-未命中 | 抽取全部条件均未命中的客户 | 等级不为 E |
| 否决-分数保留 | 查看 E 客户 `score` | 分数正常输出，不为空 |
| 加分-单条规则 | 逐条构造命中/未命中样本 | 命中 +5，未命中 +0 |
| 加分-规模/技术流 | `entp_scl=中型/大型`、`rt_rslt_id='1'/'2'` | 均应 +5 |
| 加分-年限叠加 | 年限 6 年 / 11 年 | +5 / +10 |
| 加分-重点产业叠加 | `wht_key_ind_cust='1'` | +10（规则 2 + 规则 11） |
| 加分-封顶 | 构造命中全部规则 | 总加分不超过 20 |
| 负分归零 | 基础分为负的客户 | 加分基数从 0 起算 |
| 阈值与分级 | 用基础分核对 A/B/C/D 分界 | 206.09 / 189.31 / 145.44 |

### 3.2 分层与排序验收

当前测试集分层：

| 等级 | 样本数 | 坏客户数 | 坏客户率 | 最低分 | 最高分 | 占比 | 口径 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 6 | 0 | 0.00% | 208.53 | 257.78 | 10.0% | 前 10% |
| B | 2 | 0 | 0.00% | 193.35 | 194.84 | 3.3% | 10%–20% |
| C | 13 | 0 | 0.00% | 151.74 | 187.64 | 21.7% | 20%–40% |
| D | 24 | 19 | 79.17% | 10.99 | 139.62 | 40.0% | 后 60% |
| E | 15 | 11 | 73.33% | 33.21 | 190.69 | 25.0% | 规则否决 |

验证要点：

- A→B→C→D 坏客户率应单调上升（当前 A/B/C 均为 0%，D 为 79.2%）；
- B 档当前仅 2 个样本，与目标 10% 有偏差，可能因小样本 Mock + 加分后分数离散导致；
- D 档坏率 79.2%，明显高于 C 档的 0%，区分度良好；
- E 为规则否决层，不要求与分数单调，但要能逐户解释命中原因；
- 高分客户应集中在 A/B，低分客户应集中在 D。

### 3.3 业务抽样回跑

建议业务方准备一批已有人工结论的客户：

1. 用 `scorecard.sql` 在 Hive 跑出 `score` 与 `customer_level`；
2. 与 `report/abcd_rule.csv`、打标结果逐户比对；
3. 重点核对否决户、加分户、跨等级边界户（贴近 182.89 / 117.64 / 17.00）。

## 七、待业务确认事项

1. 加分权重：当前统一按 5 分/项落地，原建议为 0.2→20 分、0.1→10 分、0.05→5 分，是否恢复原权重；

3. E 客户处置：仅等级置 E、分数保留，是否还需要人工复核或禁止营销；
4. `reg_st` 缺失口径：当前缺失也判 E，是否符合实际数据质量；
5. 分级阈值：当前按训练集 75/50/25 分位，是否按业务目标坏率重新校准；
6. 名单字段范围：是否需要补充“经营异常”等新字段。

## 八、复现与交付

```bash
# 1. 训练并生成 SQL
python run.py train --scenario industry_finance

# 2. 本地评估并生成报告
python run.py evaluate --scenario industry_finance

# 3. 生产执行评分卡
hive -hivevar bizdate=20261031 -f scenarios/industry_finance/report/scorecard.sql
```

生产切换要点：

- `data.load_mode` 改为 `spark`；
- `source.database` / `source.table_name` 改为真实库表；
- 用真实正负样本替换 `pos_sample_ids.csv` / `neg_sample_ids.csv`；
- 重新运行训练与评估，确认指标后再发布 SQL。
